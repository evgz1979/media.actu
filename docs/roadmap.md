# Реализованное и план

Сверено с исходниками 2026-11-03. Версия продукта остаётся `0.1.0-dev`.
Чекбоксы обозначают фактическое наличие сценария в коде, а не независимый аудит
рабочих данных M4. Исторические названия этапов сохранены в Git и ADR; ниже — текущее состояние.

## Реализовано

- [x] Раздельные FastAPI Core и NiceGUI UI, loopback-порты и схема SSH-туннеля.
- [x] Два SQLite-каталога, сохранённые источники, тома, снимки папок и история.
- [x] Две панели, обычные деревья по уровням, превью и плитки папок.
- [x] Фото и кадры видео вне индекса через FFmpeg либо AVFoundation на macOS.
- [x] Поиск NAS, запоминание ресурсов и подключение через Finder.
- [x] Устойчивые маркеры сменных носителей, проверка отключения/замены и архив томов.
- [x] Основные папки и копии, типы, отключение, освобождение и упорядочивание номеров.
- [x] Источник копирования: основная либо другая копия своего набора, запрет циклов.
- [x] Служебные описания зарегистрированных папок с постоянной очередью записи.
- [x] Метки папок и отслеживание изменений основных папок.
- [x] Фоновые логические размеры папок с частичностью и stale.
- [x] Общая сверка имён с сохранёнными индексами и историей.
- [x] Парная структура, путь/размер, дополнительный SHA-256 и решения для extra_copy.
- [x] Виртуализация связанных деревьев и синхронизация выбора/прокрутки.
- [x] План, подтверждение, журнал и остановка создания отсутствующих копий без замены.
- [x] Отдельные профили Photos, идентификация якорями, годы/месяцы и страницы объектов.
- [x] Постоянный PhotoKit-helper, локальные фото-превью и постеры видео.
- [x] Манифест оригиналов, квитанции версии/stat и продолжение без повторного хеширования.
- [x] Ограниченный буфер 64 МиБ и прямая запись оригинала в новую конечную цель.
- [x] Цепочки Photos-копий и приоритет уже сохранённых ресурсов.
- [x] Необязательное окно работы Photos по Москве и постоянные запросы расписания.
- [x] Восстановление навигации вкладки и браузерные настройки боковых секций.
- [x] Подробная документация, справочник определений и двухстрочные пояснения к коду.

Ограничения каждого сценария описаны в [архитектуре](architecture.md),
[безопасности](safety-and-recovery.md) и [сквозных сценариях](flows.md).

## Неполные общие возможности

- [ ] Единый поиск/фильтрация по всему пользовательскому медиаархиву: нынешние
  фильтры отчётов и пагинация отдельных списков не являются общей системой поиска.
- [ ] Полное извлечение EXIF и видеометаданных: сейчас используются только нужные
  метаданные индекса/превью и отдельные системные поля Photos.
- [ ] Политика независимых проверенных экземпляров: количество зарегистрированных
  связей не подтверждает число исправных резервных копий.
- [ ] Автоматическое резервирование баз и проверенный пользовательский сценарий восстановления.
- [ ] Версионируемые снимки файлового состояния: пути, параметры, размещение
  экземпляров и связь с журналом операций, без копирования самих оригиналов в снимок.
- [ ] Единый аудит всех управляемых файловых операций и проверенный сценарий отката.
- [ ] Универсальный механизм миграций с отдельными версиями схем: сейчас службы
  создают и расширяют таблицы при инициализации.
- [ ] Общая отчётность о потерянных/повреждённых экземплярах по всему архиву.

## Входящие носители и импорт

- [ ] Профиль входящего носителя, отличающий импортируемые данные от зарегистрированной копии.
- [ ] Предварительный план импорта без автоматического изменения источника.
- [ ] Правила размещения импортируемого набора и проверка результата до изменения
  политики дальнейшего хранения. Обнаружение диска и копирование отсутствующего
  уже работают, но сами по себе не реализуют весь сценарий управляемого импорта.

## Поиск ненужных файлов

- [ ] Восстановить критерии и исключения из прежнего обсуждения пользователя.
- [ ] Показывать кандидатов и причины с ручным решением.
- [ ] Сохранять результаты в каталоге; не удалять файлы автоматически.

## Дедупликация и перестройка

- [ ] Отдельный сценарий точных дубликатов по SHA-256: имеющаяся сверка пары сама
  по себе не является глобальной дедупликацией.
- [ ] Визуальное сходство, perceptual hash и группировка связанных sidecar-файлов.
- [ ] Выбор главного экземпляра, правила структуры по дате/событию/устройству.
- [ ] Симуляция нового дерева и обнаружение конфликтов.
- [ ] Изменение существующих оригиналов только после отдельной реализации плана,
  подтверждения, журнала, карантина и проверяемого отката.

## AI-анализ и экспортные профили

- [ ] Локальные либо явно выбранные облачные модели, описания сцен и качества.
- [ ] Лица только при отдельном включении, версия модели/промпта, уверенность результата
  и возможность удаления производных данных; географические и событийные группы.
- [ ] Экспортные профили для личных, рабочих и сайтовых наборов: отбор, преобразования,
  назначение и правила имён. Текущий UI не содержит готового редактора таких профилей.
- [ ] Предварительный расчёт состава экспорта без записи и журнал проверенных результатов.
- [ ] Обработка скриншотов: извлечение текста и производные версии.
- [ ] Изменение политики хранения оригиналов только отдельной подтверждаемой операцией.

## Возможная отдельная очистка

- [ ] Повторно проверить кандидатов из [реестра старых частей](legacy.md) с учётом
  внешних скриптов, Launcher и старых баз.
- [ ] Отдельно согласовать удаление, миграцию или сохранение совместимости.

В текущей работе старые определения, скрипты, поля, таблицы и оформление сохранены.
