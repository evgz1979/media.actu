## Как читать ссылки и ограничения анализа

Ссылки на определения ведут к устойчивым якорям справочника. В каждой записи
указаны путь исходного модуля, полное лексическое имя и сигнатура. В справочнике
есть индекс вложенных обработчиков, например `PhotosOriginals._save.flush`.

Статический список вызовов показывает выражения в собственном теле определения.
Он не доказывает выполнение каждой ветви и не разрешает все динамические callback.
Методы FastAPI, Vue, Watchdog и стандартных базовых классов могут вызываться
фреймворком без прямого упоминания имени из другого Python-метода. Поэтому
список «нет текстовых вызовов» используется только как кандидат для проверки,
а не как разрешение удалить код.

## Стиль пояснений в исходниках

Перед каждым именованным классом, функцией и методом Python — две строки `#:` комментария:
действие/результат и существенное условие либо наблюдаемый контракт. Пояснение стоит
перед декораторами, если они есть. Старые docstring и технические заметки сохранены.
Комментарии не меняют `__doc__` и исполняемые конструкции; это проверяется сравнением AST.
У нативных функций и методов Vue используются двухстрочные блоки `//:`, у AppleScript — `--:`.
Анонимные lambda, arrow-функции и Objective-C blocks объясняются
в контексте владельца; отдельного имени для ссылки у них нет.

Подробные алгоритмы и списки связей находятся здесь, чтобы две строки возле метода
не превращались в повторение длинного руководства. Старые определения тоже описаны,
а их текущий статус указан в [реестре](../legacy.md).
