# Развёртывание на M4

Версия документа: `2.0.0`
Применимо к продукту: `0.1.0-dev`

Статус: рабочая схема

Сверено с репозиторием: `2026-11-03`.

Адреса и роль машин отражают принятую рабочую схему. Запущенный экземпляр M4,
разрешения Photos и внешняя конфигурация Launcher в рамках этой сверки не опрашивались.
Исторические сведения о путях Launcher ниже нужно проверять на целевой машине;
они не подтверждают, что удалённый процесс уже использует текущую версию исходников.

## Машины и данные

- Mac mini M4 (`macmini-m4.local`) — рабочие Core и UI, существующая база, кэш,
  подключённые носители и системная медиатека Photos.
- Ноутбук — разработка, подготовка изменений, развёртывание на M4 и браузерный доступ.
- Папка проекта на обеих машинах: `/Users/evgz/Documents/media.actu`.
- База и кэш M4 не заменяются при развёртывании исходников. `.venv/`, `data/`,
  `config.local.json` и `launcher.json` остаются локальными для каждой машины.
- Пока изменения исходников не согласованы, существующий код M4 не обновляется.

## Запуск

На M4 Core запускается существующим интерпретатором `.venv/bin/python`:

```sh
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 18765
```

Локальный `launcher.json` M4 содержит оба сервиса. Core и UI по умолчанию
используют адрес Core `http://127.0.0.1:18765`. Стартовая страница `/` —
хранилища и медиатеки Photos в общих панелях; `/media` перенаправляет на главную. Базы
`data/catalog.sqlite3`, `data/storage.sqlite3` и кэш при обновлении не заменяются.

С ноутбука открываются только SSH-туннели:

```sh
ssh -N -T -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:18090:127.0.0.1:8090 \
  -L 127.0.0.1:18765:127.0.0.1:18765 \
  evgz@macmini-m4.local
```

После подключения интерфейс доступен по `http://127.0.0.1:18090`.
На ноутбуке для работы с данными M4 отдельные Core и UI не требуются.

### Вывод сервисов в Launcher

Текущий Launcher создаёт для stdout/stderr канал без чтения. После заполнения
канала запись журнала может заблокировать сервис. Для фонового запуска команды
Core и UI оборачиваются в `media_manager.service_runtime`, сохраняя прежние
аргументы и sandbox:

```sh
.venv/bin/python -m media_manager.service_runtime core -m uvicorn app:app --host 127.0.0.1 --port 18765
.venv/bin/python -m media_manager.service_runtime ui -c 'import ui; ui.ui.run(host="127.0.0.1", port=8090, reload=False, show=False)'
```

Рабочие параметры UI, включая `CORE_URL`, заголовок и storage secret,
сохраняются из действующей команды Launcher. Журналы `data/logs/core.log` и
`data/logs/ui.log` ограничены 2 МБ, сохраняются три предыдущих файла.
`SIGUSR1` записывает стек в `data/logs/core-stacks.log` или `ui-stacks.log`;
сигнал посылается только процессу, запущенному через эту обёртку.

## Photos и сохранность данных

Доступ к Photos выполняется в пользовательском GUI-сеансе M4. Для постоянной
работы используется Launcher на самом M4; SSH служит для развёртывания и туннеля.
Запуск адаптера непосредственно из SSH может вызвать запрос управления Photos
от имени `sshd-keygen-wrapper`. Такое разрешение не следует выдавать автоматически.

Существующие пользовательские оригиналы не изменяются. Создание отсутствующих
копий и сохранение ресурсов Photos в отдельные назначения разрешены явными командами;
служебные маркеры носителей и папок могут обновляться отдельно. Собственная SQLite-база, журналы и производный
кэш превью являются рабочими данными приложения. Перед первым запуском на M4
2026-10-28 сохранена согласованная резервная копия базы в `data/backups/`.
Отключённые носители нельзя считать утраченными файлами: сохранённый индекс
нужно отличать от актуального результата проверки.


## Поиск NAS

Поиск NAS и чтение ресурсов выполняются на M4. Нужны штатные `/usr/bin/dns-sd`
и `/usr/bin/smbutil`; новые пакеты не устанавливаются. Для получения ресурсов
используется существующий доступ macOS без запроса пароля. Подключение ресурса
открывается в Finder на M4 только по отдельной команде пользователя.

Для изолированных проверок Core поддерживает `MEDIA_ACTU_DATA_DIR` с отдельной
папкой тестовых баз. Рабочий Launcher не задаёт эту переменную и использует
обычную папку `data/`. При проверке UI используется `--lifespan off`, чтобы
не запускать сканеры, очередь превью и адаптер Photos.

## Регистрация сменных дисков

Core на M4 запускается в `sandbox-exec` с запретом записи под `/Volumes`.
Для согласованной регистрации и переименования носителей в его профиле разрешены
создание, запись и атомарная замена одного служебного имени в корне тома:

```scheme
(allow file-write-create file-write-data file-write-unlink
  (regex #"^/Volumes/[^/]+/[.]media-actu-volume[.]json$"))
```

Промежуточный JSON использует уже разрешённое имя `.media-actu-copy-…-….part`;
оно исключено из дерева и сверок, удаляется при завершении или ошибке операции.
Исключение относится только к Core; UI не получает права записи на исходные
тома. Разрешение записи кэша `/Volumes/nvme2Tb/media.actu-cache` сохраняется.
Действующая версия Launcher на M4 пока читает команды из
`/Users/evgz/Documents/launcher.actu/configs/mac-mini-evgenij.json`.
Правило Core согласовано там и в проектном `launcher.json`; прежние значения
автозапуска сохранены. При обновлении Launcher нужно учитывать оба источника.
Базы при развёртывании не заменяются. Регистрация не переносит старую историю
`usbshare` на новый ID автоматически.

## Создание отсутствующих копий

Для описаний зарегистрированных папок Core дополнительно использует правило из
`media_manager.sandbox_rules.folder_marker_write_rules()`:

```scheme
(allow file-write-create file-write-data file-write-unlink
  (regex #"^/Volumes/[^/]+/.+/[.]media-actu-folder[.]json$"))
```

Оно разрешает запись только этого служебного имени в папках томов. Промежуточные
файлы используют существующее разрешение `.media-actu-copy-…-….part`. Профиль UI
не меняется. Маркеры записывает только Core; состояние очереди доступно через
`GET /api/storage/folder-markers`. При обновлении процесса нужно дождаться
завершения активного копирования и сохранить резервную копию базы.

Для Core к прежнему профилю добавлены правила из
`media_manager.sandbox_rules.copy_write_rules()`: создание новых путей под
`/Volumes` и операции с собственными промежуточными файлами копирования.
Общий запрет записи данных в существующие файлы и их удаления сохраняется;
профиль UI остаётся прежним. План фиксирует выбранный источник →
назначение; по умолчанию источник `00-main`, но может быть другой копией набора; перед стартом и публикацией проверяются обе папки и диски.
Подробнее: [ADR-0004](adr/0004-copy-missing-only.md).


## Конфигурация, состояние и проверка запуска

`MEDIA_ACTU_DATA_DIR` задаёт базовый каталог Core и журналов; без него используется
проектный `data/`. `config.local.json` переопределяет только каталог JPEG через
`thumbnail_cache_directory`; пример хранится в `config.example.json`. `.nicegui/`
относится к UI и не переносится этой переменной автоматически. Не заменяй локальные
базы и конфигурацию M4 при доставке исходников.

Импорт `app.py` создаёт объекты служб и выполняет SQLite-инициализацию даже с
`--lifespan off`. Для любого изолированного запуска сначала задай отдельный каталог
данных; отключение lifespan предотвращает запуск наблюдателей/PhotoKit-очередей,
но не создание таблиц. Обычный запуск `python app.py` использует 18765, `python ui.py`
— 8090; обе команды предполагают уже установленное окружение requirements.txt.

Проверки после согласованного запуска:

1. Убедиться, что выбран правильный экземпляр данных и процессы слушают нужные loopback-порты.
2. Проверить `/health` и `/docs` Core, затем главную UI.
3. Сопоставить тома и статусы идентичности; снимок offline не считать живым чтением.
4. Проверить настроенный том JPEG-кэша и отсутствие скрытого перехода на другой диск.
5. На M4 в GUI-сеансе проверить доступ PhotoKit и нужный профиль медиатеки.
6. Перед возобновлением записи изучить активные задания и журналы; не начинать
   копирование только ради проверки доступности страницы.
