## Правила версионирования

1. Документация хранится в Git рядом с кодом.
2. `docs/VERSION` следует за версией продукта из корневого `VERSION`.
3. Изменение поведения должно сопровождаться изменением соответствующей документации в том же коммите.
4. Выпущенная версия документации восстанавливается по Git-тегу продукта `vX.Y.Z`.
5. Принятые ADR не переписываются по смыслу. Новое решение создаёт новый ADR и помечает старый как заменённый.
6. Все заметные изменения документации фиксируются в `docs/CHANGELOG.md`.

Отдельные копии документации по версиям не создаются: Git-теги дают точный снимок кода и документов без расхождений.
