## ADR

ADR сохраняют историю решений. Заметки сверки показывают нынешнюю реализацию и
различия с ранними этапами; старые тексты не следует читать как единое описание
текущего продукта.

## Правила актуализации

1. Документация и код хранятся вместе в Git. Изменение поведения обновляет
   руководство, API/схему, языковой разбор, справочник затронутых определений и тесты.
2. `docs/VERSION` следует за корневым `VERSION`; документационная работа сама
   по себе не объявляет новый выпуск приложения.
3. Ссылка на определение использует полное лексическое имя и устойчивый якорь
   справочника. В записи сохраняется ссылка на исходный модуль.
   Актуальность проверяется сравнением заново построенного смыслового описания.
4. Для старой части указывается статус и доказательство; отсутствие прямого
   вызова не доказывает, что framework-callback или внешний CLI больше не нужен.
5. Принятый ADR сохраняет смысл исторического решения. Замена решения требует
   отдельного ADR; заметка проверки может уточнить текущее состояние реализации.
6. Изменения отражаются в [журнале документации](CHANGELOG.md), ограничения
   проверок — в [протоколе](validation.md).
7. Выпущенные состояния восстанавливаются по Git-тегам продукта `vX.Y.Z`;
   копии полного каталога docs для каждой версии не создаются.
