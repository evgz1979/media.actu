# Старые части, совместимость и неиспользуемые определения

Сверка исходников: **2026-11-03**. Ничего из перечисленного не удалено.
Это карта состояния кода, а не утверждение о том, что внешних клиентов или сохранённых
данных больше нет. Поиск охватывал исходники, тесты, импорты, имена файлов, строковые
ссылки и регистрацию callback; работа запущенного M4 отдельно не трассировалась.

## Как понимать статус

- **Вызовов в текущем коде не найдено**: проверенное статическое наблюдение,
  а не доказательство отсутствия внешнего вызова.
- **Недостижимая старая ветвь**: сама содержит код, но текущая цепочка входов её не вызывает.
- **Совместимость**: старый адрес, формат или схема продолжают обслуживаться.
- **Действующая старая подсистема**: историческое происхождение не делает её неиспользуемой.
- **Кандидат оформления**: селектор найден в CSS, но не найден в создаваемой проектом разметке.

Для этих частей при будущей очистке потребуется повторный поиск в конфигурациях
Launcher, ручных командах и внешних скриптах. В этой работе они лишь описаны и
получили комментарии, функциональная реализация сохранена.

Тест, подтверждающий отсутствие scripting fallback при отказе PhotoKit:
[test_photos_adapter.py](../tests/test_photos_adapter.py).
Не следует смешивать `export.applescript` с [open.applescript](../photos_adapter/open.applescript):
второй сейчас вызывается для выделения объекта в системном Photos.

## Действующая совместимость и старые подсистемы

| Модуль или ветвь | Почему используется |
| --- | --- |
| comparison_ui.py | ui.py регистрирует /compare → / с параметрами и 307 |
| ui.old_media_page | /media перенаправляет на виртуальную Photos-область главной |
| comparison.py / ComparisonCatalog | История, общая сверка имён, сохранённые деревья и общие функции безопасного чтения |
| comparison_tree_ui.py | workspace_ui создаёт дерево найденных путей правой панели |
| storage_ui.py | Общий CSS, SVG папки, двойной клик и действующая регистрация workspace |
| network_ui.py | Кнопка «Найти NAS» вызывает диалог серверов и ресурсов |
| scanner.py / watcher.py / sources API | Сохранённые обычные folder-источники по-прежнему сканируются, наблюдаются и обслуживаются API |
| status/check CLI helper | Используется не-GUI проверкой разрешения и остаётся явной CLI-точкой входа |
| scan/thumbnail CLI helper | Доступны из main по явной команде; нынешний UI использует постоянный протокол |
| stdin/stdout transport helper | Используется не-GUI режимом и fake-helper тестами |
| sandbox_rules.py | Генератор правил для внешней конфигурации Launcher и тестов, а не служба lifespan |
| ServiceFileHandler.handleError, encoding, writable | Вызываются протоколом logging/io и базовых классов без обязательного прямого вызова по имени |

Начальная модель source/storage, пользовательские annotations.role и современная
модель main/copy/cold/cloud — три разные системы. Старые роли остаются данными и API,
но не должны описываться как нынешний единственный способ учёта копий.

## Кандидаты старого оформления

В CSS [storage_ui.py](../storage_ui.py) остаются `s-header`, `s-nav`, `s-intro`,
`s-layout`, `s-properties`, `s-readonly` и responsive-правила для прежнего макета.
За пределами определения CSS их назначения в создаваемой текущим проектом разметке
не обнаружены. Это кандидаты для отдельной визуальной проверки, не основание удалить
весь CSS: `s-panel`, `s-tree`, строки, иконки и многие другие правила используются.

## Используемый устаревающий API

В PhotoKit-helper используется `PHAssetResource.originalFilename`. Нативная
синтаксическая проверка выдаёт пять предупреждений SDK о deprecated API начиная
с macOS 27. Оно участвует в выборе имени и сортировке ресурсов; это действующий
код, а не кандидат на удаление. Подробности и ссылки на функции:
[нативный справочник](development/native.md). Миграция на другую системную API
в документальную работу не включалась.

У Photos также различаются версия оригинального ресурса и ключ JPEG-превью:
последний использует `media_files.modified_at`, получаемый из даты создания
обычного скана. Нельзя обещать автоматическое обновление готовой миниатюры
по каждой версии манифеста оригиналов. Это ограничение зафиксировано в
[разборе протокола](development/photos-protocol.md).

## Где прежняя документация расходилась с кодом

| Прежнее утверждение | Уточнение текущей реализации |
| --- | --- |
| Всё приложение только на чтение | Разрешены новые копии, оригиналы Photos и собственные служебные файлы |
| Все изменяемые данные только в data | Есть внешний JPEG-кэш, .nicegui и явно выбранные папки копий/маркеры на томах |
| Журнал и планы только в будущем | Для сверок, копирования и Photos они уже существуют; общего отката нет |
| Все деревья строятся целиком / все деревья ленивые | Реализация различается: медиаиндекс, уровни обычных папок, страницы Photos, виртуализация пары |
| Ночное ограничение включено по умолчанию | DEFAULT.night_only=False, часы 00–07 используются при включении |
| Сделать Photos-копию первой значит перенаправить источники | Метод меняет номера; источники настраиваются отдельно |
| Пауза превью означает паузу оригиналов | Управления независимы; временное окно дополнительно ограничивает работу |
| Есть информационная секция экспорта | В текущем рабочем пространстве такая секция не найдена; экспортные профили — план |

Новые документы отражают поведение кода. Принятые ADR сохранены как история решений
и дополнены заметками о текущем статусе и точках реализации.

## Правило дальнейшей актуализации

При возвращении старой части в работу измени её статус и добавь тест новой точки
входа. При будущей очистке отдельно рассмотри данные старых баз, внешние вызовы,
миграцию, чтение истории и обратную совместимость ссылок. Удаление не входит в
нынешнюю документальную работу и требует отдельной задачи.
