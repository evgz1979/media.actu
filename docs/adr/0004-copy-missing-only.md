# ADR-0004: создавать только отсутствующие копии

Статус: принято по прямой команде пользователя
Дата: 2026-10-30

## Область

После файловой сверки разрешено явно скопировать отсутствующие файлы и папки
из зарегистрированной `00-main` в одну зарегистрированную копию. Существующие
пути сохраняются, в том числе файлы другого размера. Лишние файлы и конфликты
типов пользователь разбирает вручную. Обратное направление отсутствует.

## Исполнение

План и состояние каждого элемента записываются в SQLite до начала работы.
Пользователь видит направления, полный список, количество и объём, затем
подтверждает запуск. Диски и корневые папки проверяются до записи и перед
публикацией файла. Пересекающиеся области, символьные ссылки, вложенные тома,
изменившиеся исходники и непроверенные носители не допускаются.

Исходник открывается только для чтения. На файловых системах с поддержкой
`RENAME_EXCL` назначение пишется в отдельный новый файл, затем после проверки
размера и неизменности исходника публикуется атомарно без замены цели.
SMB TerraMaster возвращает `ENOTSUP` и для `RENAME_EXCL`, и для жёстких ссылок.
Поэтому сетевые копии создаются под целевым именем через `O_CREAT | O_EXCL`:
существующий путь всегда пропускается, подмена не допускается.
Если атомарная публикация не поддерживается другим диском, используется тот же
способ. Хэширование остаётся отдельным методом сверки по выбору пользователя.

Стоп убирает собственный промежуточный файл, оставляя готовые копии. При прямой
записи незавершённый файл сохраняется и получает отметку «Копия не завершена»:
он не считается совпавшим даже при равном размере. Автоматического удаления или
перезаписи такой цели нет; её пользователь разбирает вручную.
Падение процесса фиксируется как прерывание; автоматического продолжения нет.
После копирования запускается новая сверка имён и размеров. История и прочие
различия сохраняются. Автоматического удаления готовых копий для отката нет:
они могли быть изменены пользователем после операции.

## Защита M4

UI сохраняет прежний запрет записи на тома. В профиле Core добавлены разрешения
создавать новые пути под `/Volumes` и изменять только промежуточные файлы с
зарезервированным именем `.media-actu-copy-<id>-<id>.part`. Конкретное назначение
проверяется неизменяемым планом и дескрипторами выбранной папки. Запись данных,
переименование и удаление остальных существующих файлов на томах остаются
запрещены профилем ОС, за прежними исключениями кэша и файла ID носителя.
Правила формирует `media_manager.sandbox_rules.copy_write_rules`.

## Проверки

Проверяются предварительный план без записи, отсутствие перезаписи при гонке,
изменение и замена исходников/целевых папок, ссылки и специальные файлы,
отключение дисков, остановка, нехватка места, перезапуск и обновление отчёта.
Отдельные интеграционные проверки macOS sandbox выполняют атомарную и прямую
запись, проверяя запрет изменения и удаления существующих файлов. Дополнительно
на настоящем SMB проверяется копирование в изолированной тестовой папке.
