# ADR-0006: продолжение сохранения Photos по метаданным

Статус: принято
Дата: 2026-11-02
Заменяет правила проверки содержимого копий оригиналов из [ADR-0005](0005-photos-libraries.md).

## Сверка реализации — 2026-11-03

Продолжение по версиям и stat действует; ctime не входит в same_file из-за особенностей SMB. Эта гарантия не равна SHA-256 содержимого. Старые checksum-колонки сохранены, но не используются для нового продолжения.

Код: [`same_file`](../../media_manager/photos_originals.py#L39), [`PhotosOriginals._reuse_receipt`](../../media_manager/photos_originals.py#L407).

Историческое решение ниже сохранено. Текущее устройство: [архитектура](../architecture.md), [реестр старых частей](../legacy.md).

## Решение

Механизм записи через временный оригинал в этом документе заменён
[ADR-0007](0007-photos-buffered-direct-write.md): буфер 64 МиБ и прямая запись
в новый конечный файл. Политика сопоставления по метаданным сохраняет силу.

Согласованная политика: **оригиналы хранятся только в привязанных папках-копиях**.
В SQLite — метаданные, задания, связи и результаты проверки. В кэше — только
производные превью. Файлы изображений не записываются BLOB-полями в базу.

Сейчас привязывается существующая папка на проверенном подключённом томе.
Привязка не создаёт файлы и не запускает выгрузку. Отвязка отключает связь в базе,
не меняя папку. Пересекающиеся назначения медиатек запрещены.

Явная команда «Сохранить оригиналы» в меню папки копии запускает отдельное задание.
Core сверяет параметры файлов назначения, затем получает список ресурсов PhotoKit.
Готовые ресурсы узнаются по ID объекта и ресурса, версии Photos, пути, размеру,
времени изменения и идентификатору файла. Содержимое сохранённых файлов не читается.
Контрольные суммы не вычисляются и не проверяются. Это постоянная политика
синхронизации медиатеки; проверка содержимого не запускается автоматически.
Привязка сама по себе не запускает скачивание.

PhotoKit Resource Manager передаёт неизменённые photo/video/audio, alternatePhoto
(RAW) и pairedVideo (Live Photo). Отредактированные fullSize-ресурсы не подменяют
оригиналы. Объект готов, только когда сохранены все его оригинальные ресурсы.
Чтение для этой явной операции допускает iCloud (`networkAccessAllowed=YES`).
Для ручных копий без записи о ресурсе используется исходное имя и размер потока,
а параметры существующего файла должны оставаться неизменными. Неоднозначные
совпадения не принимаются. Переименованные ручные файлы по содержимому не ищутся.
PhotoKit не отдаёт размер оригинала в манифесте: такое первичное сопоставление
может требовать передачи ресурса, но не чтения существующего файла. Внутренним кэшем Photos
управляет macOS; приложение не создаёт промежуточные оригиналы вне копии.

Каждый поток пишется в принадлежащий заданию `.media-actu-copy-*.part` внутри копии.
После `fsync` сверяются количество переданных байтов и размер файла через `stat`.
Повторного чтения для проверки нет. Совпавший существующий файл учитывается по его фактическому пути,
промежуточный удаляется. Новые файлы размещаются в `ГГГГ/ГГГГ-ММ` по исходному имени;
без даты — в «Без даты». При конфликте добавляется числовой суффикс.
Публикация не заменяет существующие пути, включая появившиеся во время операции.
Если SMB не поддерживает exclusive rename, создаётся только новый конечный файл
с `O_CREAT|O_EXCL`: временный файл читается только для этой публикации, без
последующего чтения результата. Незавершённые конечные
файлы после сбоя сохраняются с записью в журнале; приложение не перезаписывает и
не удаляет их, при повторе выбирает свободное имя.

Запись копии хранит ID медиатеки, ID объекта и ресурса, версию, относительный путь,
размер и параметры файла. Старые поля контрольных сумм остаются для совместимости
базы, но больше не используются. Эти сведения сохраняются независимо от пересканирования каталога.
Готовность превью и подтверждённое наличие оригинала учитываются отдельно.
На кнопке медиатеки — отдельный прогресс для каждой копии. Её меню содержит запуск,
паузу/продолжение и журнал. Одновременно работает одно задание оригиналов.
После перезапуска активное задание переходит в паузу; продолжение пропускает готовые
ресурсы по метаданным. Общий прогресс восстанавливается из постоянных записей копии,
не обнуляется при обновлении манифеста; прерванное обновление не удаляет прежние строки.
Текущий частичный ресурс передаётся заново.
Отключение тома, отвязка папки, замена её корня, смена медиатеки и нехватка места
останавливают задание. Обход каталогов не следует симлинкам и не пересекает тома.
