# ADR-0007: буферизация и однопроходная запись оригиналов Photos

Статус: принято
Дата: 2026-11-02
Заменяет временные оригиналы и публикацию через копирование из [ADR-0006](0006-photos-metadata-resume.md).

## Решение

Core собирает входящие блоки PhotoKit в ограниченный буфер памяти размером
64 МиБ. Полный буфер записывается последовательно, остаток — при завершении
ресурса. Одновременно сохраняется один ресурс; размер видео не определяет
потребление памяти. Новые оригиналы не помещаются во временные файлы приложения.

Первая запись создаёт сразу конечный файл внутри привязанной папки копии,
используя `O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW`. Это единый путь для локальных
и сетевых назначений. При занятом имени выбирается числовой суффикс. Существующий
файл никогда не открывается для записи. Переименований и повторного копирования
оригинала для публикации больше нет.

Перед первой записью в SQLite сохраняются путь и идентификатор созданного файла.
Незавершённый файл виден в папке, остаётся в журнале и исключается из поиска
готовых файлов. При повторе выбирается свободное имя; приложение не удаляет
и не перезаписывает незавершённые конечные файлы. Старые принадлежащие приложению
временные `.part` могут быть удалены прежним механизмом очистки после проверки
идентификатора; чужие файлы не удаляются.

Пауза проверяется между входящими блоками, перед записью буфера и при коротких
системных записях. При паузе незаписанный буфер отбрасывается, завершённые ресурсы
и общий прогресс сохраняются. Текущий незавершённый ресурс передаётся заново.

Готовность фиксируется после завершения потока PhotoKit, сверки размера,
`fsync`, закрытия пишущего дескриптора и сверки идентификатора и размера через
метаданные. Запись готовности и удаление признака незавершённого файла выполняются
одной транзакцией. Содержимое результата не перечитывается.

Свободное место запрашивается перед первой записью ресурса, затем не чаще раза
в пять секунд, пока сохранённой оценки достаточно с резервом 64 МиБ. Каждый
записанный блок вычитается из оценки. При приближении к резерву объём проверяется
снова. Ошибка записи останавливает учёт ресурса как готового.

Ручная копия без записи Photos может быть принята по имени, размеру и неизменным
параметрам, пока весь ресурс находится в буфере и новый файл ещё не создан.
Для больших ресурсов после начала записи сохраняется новый конечный файл;
существующие ручные файлы остаются нетронутыми. Ранее зарегистрированные ресурсы
любого размера пропускаются по метаданным до передачи.

Политика [ADR-0006](0006-photos-metadata-resume.md) о сопоставлении по метаданным,
сохранении прогресса и отсутствии автоматического чтения содержимого сохраняется.
Ночное расписание и привязки копий не меняются.
