# ADR-0005: медиатеки Photos и привязанные копии

Статус: принято
Дата: 2026-10-31

## Сверка реализации — 2026-11-03

Профили и локальные превью действуют. Ранние части описания проверки оригиналов уточнены ADR-0006 и ADR-0007: готовность определяется версией и stat, запись прямая через буфер. Окно работы по умолчанию выключено (night_only=False), часы по умолчанию 00–07. Ручные паузы превью и оригиналов независимы.

Код: [`PhotoLibraries.refresh_connection`](../../media_manager/photo_libraries.py#L96), [`PhotosSyncSchedule.settings`](../../media_manager/photos_schedule.py#L73).

Историческое решение ниже сохранено. Текущее устройство: [архитектура](../architecture.md), [реестр старых частей](../legacy.md).

## Источники и идентификация

Каждая медиатека имеет постоянный внутренний ID, название, каталог, очередь
превью и привязки папок-копий. Для разных Apple ID пользователь открывает
отдельные системные медиатеки в Photos на M4. Приложение не входит в Apple ID
и не хранит его пароль. Смена аккаунта внутри того же файла медиатеки не позволяет
разделить уже смешанные в Photos объекты.

PhotoKit читает текущую системную медиатеку. Остальные записи доступны по
сохранённому каталогу и кэшу, их очередь не исполняется. Сопоставление выполняется
по выборке ID объектов: нужны минимум три совпадения либо все, если ID меньше трёх.
Неизвестный или неоднозначный набор требует отдельной записи и не заменяет старый
каталог. Helper проверяет привязку при каждом запросе и наблюдает недоступность
медиатеки. Это внутренние записи приложения, а не автоматическое определение Apple ID.

## Превью

Служебный Unix-сокет находится в отдельной папке `/private/tmp/media-actu-photos-v2-<uid>`
с правами `0700`, сам сокет — `0600`. Проверяются владелец папки и UID клиента;
блокировка исключает запуск двух серверов. Helper запускается без аргументов:
Launch Services игнорирует аргументы от sandbox-процесса. Для превью helper возвращает готовый JPEG через этот канал; кэш записывает Core.
Отдельный клиент того же сервиса принимает потоки оригиналов, поэтому длинная
передача не блокирует запросы превью. Закрытие клиента не завершает других клиентов. Helper не получает права записи в Documents и на том кэша.

Постоянный подписанный PhotoKit-helper работает в GUI-сеансе M4. Между запросами
сохраняется процесс и менеджер изображений. Запрашиваются локальные небольшие
изображения с `networkAccessAllowed=NO`, `HighQualityFormat` и быстрым изменением размера.
`FastFormat` не используется: на M4 он возвращал миниатюры всего 64 пикселя.
Для видео сохраняется постер. Недоступная локальная миниатюра откладывается;
остальная очередь продолжается. Повторная попытка — через час либо по команде
продолжения. Открытый в просмотре раздел получает приоритет.

Оригиналы ради превью не экспортируются и не скачиваются приложением ни в `data/`,
ни в кэш, ни во временный каталог. Старый полный экспорт через AppleScript больше
не используется. При отсутствии доступа показывается кнопка запроса разрешения
Фото на M4. Существующие ID объектов и готовые файлы кэша сохраняются при миграции.
Медиатека имеет собственную паузу; её продолжение не снимает паузу обычных папок.
Общая кнопка паузы может приостановить обе очереди.

## Копии оригиналов

Правила проверки содержимого в этом разделе заменены [ADR-0006](0006-photos-metadata-resume.md)
от 2026-11-02: сохранение и продолжение используют только метаданные. Остальные
правила хранения оригиналов, привязок и расписания сохраняют силу.

Согласованная политика: **оригиналы хранятся только в привязанных папках-копиях**.
В SQLite — метаданные, задания, связи и результаты проверки. В кэше — только
производные превью. Файлы изображений не записываются BLOB-полями в базу.

Сейчас привязывается существующая папка на проверенном подключённом томе.
Привязка не создаёт файлы и не запускает выгрузку. Отвязка отключает связь в базе,
не меняя папку. Пересекающиеся назначения медиатек запрещены.

Явная команда «Сохранить оригиналы» в меню папки копии запускает отдельное задание.
Сначала PhotoKit передаёт текущий список ресурсов, затем Core проверяет содержимое
существующих файлов в копии по SHA-256. Совпадение имени не считается доказательством.
Для неизменившихся файлов кэшируется отпечаток метаданных и контрольная сумма.
Привязка сама по себе не запускает скачивание.

PhotoKit Resource Manager передаёт неизменённые photo/video/audio, alternatePhoto
(RAW) и pairedVideo (Live Photo). Отредактированные fullSize-ресурсы не подменяют
оригиналы. Объект готов, только когда проверены все его оригинальные ресурсы.
Чтение для этой явной операции допускает iCloud (`networkAccessAllowed=YES`).
PhotoKit не предоставляет готовую контрольную сумму: первичное сопоставление
ручной копии тоже может требовать передачи оригинала. Внутренним кэшем Photos
управляет macOS; приложение не создаёт промежуточные оригиналы вне копии.

Каждый поток пишется в принадлежащий заданию `.media-actu-copy-*.part` внутри копии.
После `fsync` размер и SHA-256 сравниваются между helper, потоком Core и повторным
чтением с диска. Совпавший существующий файл учитывается по его фактическому пути,
промежуточный удаляется. Новые файлы размещаются в `ГГГГ/ГГГГ-ММ` по исходному имени;
без даты — в «Без даты». При конфликте добавляется числовой суффикс.
Публикация не заменяет существующие пути, включая появившиеся во время операции.
Если SMB не поддерживает exclusive rename, создаётся только новый конечный файл
с `O_CREAT|O_EXCL`, затем также проверяется полным чтением. Незавершённые конечные
файлы после сбоя сохраняются с записью в журнале; приложение не перезаписывает и
не удаляет их, при повторе выбирает свободное имя.

Проверка копии хранит ID медиатеки, ID объекта и ресурса, версию, относительный путь,
размер и SHA-256. Эти сведения сохраняются независимо от пересканирования каталога.
Готовность превью и подтверждённое наличие оригинала учитываются отдельно.
На кнопке медиатеки — отдельный прогресс для каждой копии. Её меню содержит запуск,
паузу/продолжение и журнал. Одновременно работает одно задание оригиналов.
После перезапуска активное задание переходит в паузу; повтор проверяет готовые
результаты и продолжает недостающее. Текущий частичный ресурс читается заново.
Отключение тома, отвязка папки, замена её корня, смена медиатеки и нехватка места
останавливают задание. Обход каталогов не следует симлинкам и не пересекает тома.

## Ночная синхронизация

У каждой медиатеки есть сохраняемый режим «Синхронизация только ночью».
По умолчанию окно — 00:00–07:00 Europe/Moscow; часы меняются в меню медиатеки,
включая интервалы через полночь. Начало включительно, окончание исключительно.
Вне окна не выдаются фоновые задания превью, не запускаются обновление каталога
и сохранение оригиналов. Чтение уже готовых превью доступно весь день.

`PhotosSyncSchedule` работает в Core независимо от открытого UI. Настройки
и намерение продолжать каждую копию сохраняются в SQLite. Остановленное
расписанием задание возобновляется в следующее окно, в том числе после перезапуска.
После завершения ночной проход не повторяется в том же окне; новое окно допускает
новую сверку и сохранение недостающего. Для повторов используется тот же рабочий
манифест, проверенные квитанции сохраняются без ежедневного дублирования каталога.
Привязка новой папки сама по себе не запускает скачивание — нужно начать сохранение.

Ручная пауза превью и каждой копии имеет приоритет над расписанием и не снимается
при наступлении ночи или изменении часов. Команда продолжения днём ставит оригиналы
в ожидание ночного окна. Изменение доступности тома или текущего Apple ID не обходит
проверки привязки; при временной ошибке повтор ограничен интервалом в пять минут.
Граница окна проверяется также при чтении, проверке и передаче блоков оригинала;
сохраняется существующая политика защиты незавершённых конечных файлов на SMB.
Режим не включает M4 и не будит спящий компьютер: Core должен работать.
