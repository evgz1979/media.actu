# media.actu

Локальный менеджер хранения и медиа: два файловых дерева, учёт основных папок и копий,
сверка, безопасное создание отсутствующих файлов и работа с медиатеками Apple Photos.

Версия продукта: `0.1.0-dev`. Документация сверена с исходниками **2026-11-03**.

Приложение читает пользовательские оригиналы и создаёт новые файлы в выбранных копиях.
Существующие пользовательские файлы не заменяет и не удаляет. Отдельно создаёт и обновляет
собственные базы, кэш, журналы и служебные маркеры носителей и зарегистрированных папок.
Точная граница операций описана в [безопасности и восстановлении](docs/safety-and-recovery.md).

## Что работает

- Две независимые панели с деревом файлов, виртуальными папками Photos и соседним превью.
- Активные и отключённые тома, сохранённые снимки каталогов, сведения о месте на диске.
- Поиск NAS через Bonjour, запоминание SMB-ресурсов и подключение через Finder на машине Core.
- Постоянные ID сменных носителей и проверка замены диска под прежней точкой монтирования.
- Основные папки `00-main`, обычные/сменные/облачные копии, отключение связей и освобождение номеров.
- Сверка структуры, файлов по пути и размеру, отдельная проверка SHA-256, история и плановые решения.
- Сохранённый план копирования только отсутствующих элементов, подтверждение, прогресс и остановка.
- Выбор основной или другой копии того же набора в качестве источника сверки и копирования.
- Отдельные профили Photos, локальные миниатюры, постеры видео и сохранение оригинальных ресурсов.
- Цепочки копий Photos, например Photos → NVMe → HDD, с использованием ранее сохранённых ресурсов.
- Настраиваемое окно работы Photos по Москве, независимые ручные паузы превью и оригиналов.
- Фоновый подсчёт логического размера папок, отслеживание изменений основной папки, пользовательские метки.
- Восстановление навигации вкладки и раскрытия боковых секций.

Равенство имени и размера не доказывает равенство содержимого. Готовность ресурса Photos
подтверждается версией и параметрами файла, без повторного чтения содержимого; это отдельная
гарантия, отличная от SHA-256. Общего удаления, перемещения, карантина и отката оригиналов пока нет.

## Процессы и рабочая машина

Рабочий экземпляр по принятой схеме находится на **Mac mini M4**. Ноутбук используется
для разработки и доступа через SSH-туннель. Текущее состояние M4 при этой сверке документации
не проверялось: описание запуска основано на репозитории, а не на опросе удалённого процесса.

| Сервис | Адрес на M4 | Назначение |
| --- | --- | --- |
| Core / FastAPI | `http://127.0.0.1:18765` | Файловая система, SQLite, фоновые службы, PhotoKit |
| NiceGUI | `http://127.0.0.1:8090` | Интерфейс и HTTP-клиент Core |
| OpenAPI | `http://127.0.0.1:18765/docs` | Контракты HTTP API |
| Вход с ноутбука | `http://127.0.0.1:18090` | Проброс UI M4 через SSH |

**Порт 8765 занят другим проектом и для media.actu не используется.**
Параметры Launcher локальны. Его существующую пользовательскую установку можно использовать
для запуска проекта. Подробные команды, туннель и ограничения GUI-сеанса — в [развёртывании](docs/deployment.md).

Точки входа: [`lifespan`](app.py#L131), [`core_request`](ui.py#L63) и
[`main`](media_manager/service_runtime.py#L91). Главная страница — `/`;
старые `/media` и `/compare` перенаправляют на неё с совместимыми параметрами.

## Данные

- `data/catalog.sqlite3`: медиаиндекс, очередь превью, профили и копии Photos, оригиналы и расписание.
- `data/storage.sqlite3`: тома, снимки папок, NAS, отметки, наборы копий, сверки, планы копирования и размеры.
- `data/native/`: локально собранный Photos-helper; не хранилище оригинальных медиа.
- `data/logs/`: ротируемые журналы при запуске через `service_runtime`.
- `.nicegui/`: серверное хранилище NiceGUI, в частности настройки раскрытия боковых секций.
- Кэш JPEG задаётся `thumbnail_cache_directory` в игнорируемом `config.local.json`;
  без настройки используется `data/thumbnails/`. Пример: [config.example.json](config.example.json).

`MEDIA_ACTU_DATA_DIR` меняет базовый каталог Core и журналов; не следует направлять тесты
в рабочие базы. Если настроенный внешний том кэша отключён, незаметного перехода на системный
диск нет. Производный кэш можно пересоздать, базы связей и истории — самостоятельные ценные данные.

## Проверка в среде разработки

Зависимости закреплены в [requirements.txt](requirements.txt). Существующая `.venv/` и
`.runtime/` локальны, в Git не входят. Основная проверка:

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Тесты работают с временными данными и подменами; часть проверок требует macOS, FFmpeg,
доступного Unix-сокета или нативного декодера. Ограничения и результат текущей сверки
указаны в [протоколе проверки документации](docs/validation.md).
