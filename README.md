# media.actu

Локальный менеджер хранения и медиа с отдельным Core-сервисом и браузерным интерфейсом.

Текущая версия: `0.1.0-dev`. На этом этапе приложение работает только на чтение.

## Разделы

- **Хранилища** (`/`) — два дерева файлов, сворачиваемые блоки томов и основных папок `00-main`, пронумерованные ссылки на копии, связанные пары со сверкой папок и файлов по имени и размеру, дополнительный SHA-256, история проверок, сохранённые снимки и комментарии. Все операции выполняются на главной.
- **Медиа** (`/media`) — существующий медиакаталог, системная медиатека Photos и сохранённые превью.

Тома, снимки и ручные отметки хранятся отдельно в `data/storage.sqlite3`.
Подробнее: [хранилища](docs/storage.md).

## Запуск

Рабочий экземпляр проекта запускается на **Mac mini M4**: там находятся база,
кэш превью, подключённые носители и системная медиатека Photos. Ноутбук используется
для разработки и развёртывания изменений на M4.

- Core на M4: `127.0.0.1:18765`.
- UI на M4: `127.0.0.1:8090`.
- Доступ с ноутбука через SSH-туннель: <http://127.0.0.1:18090>.

**Порт 8765 занят проектом «Зигзаг · Заказы» и для media.actu не используется.**
Core и UI теперь по умолчанию используют адрес Core `127.0.0.1:18765`.
Локальная конфигурация Launcher также явно закрепляет этот порт.

Параметры запуска хранятся в локальном `launcher.json`. Схема размещения,
туннель и особенности разрешений Photos описаны в [развёртывании](docs/deployment.md).

## Безопасность версии 0.1

- выбранные источники и все вложенные папки сканируются рекурсивно;
- символические ссылки пропускаются;
- Core читает имена, размеры, даты и содержимое фото для создания превью;
- SQLite-каталог хранится в `data/`, а превью — только в настроенном кэше приложения;
- Core строит превью в фоне даже при закрытом браузере и продолжает очередь после перезапуска;
- путь кэша задаётся в `config.local.json`; на текущей машине он вынесен на внешний NVMe;
- кэш распределён по вложенным хеш-каталогам и может быть полностью пересоздан;
- исходные папки не изменяются;
- UI не имеет прямого доступа к файловой системе и базе.

## Системная медиатека Photos

На macOS приложение автоматически показывает предустановленный источник
`Системная медиатека Photos`. Доступ выполняется отдельным локальным адаптером
системных API Photos: PhotoKit либо официального scripting API в качестве
совместимого fallback. При первом запуске macOS может запросить разрешение на
доступ к Фото или управление приложением Photos.

В версии 0.1 адаптер только читает метаданные и создаёт превью в `data/`.
Содержимое пакета `.photoslibrary` напрямую не открывается и не изменяется.

Развёрнутая документация: [`docs/README.md`](docs/README.md).
